# Token Maker SEO 深度审查报告（2026-04-30）

## 1) 执行摘要
- **总体评级：B（基础架构扎实，但内容层与索引治理还有明显提升空间）**。
- **当前优势**：
  - 已具备 `robots`、`sitemap`、canonical、`hreflang`、Open Graph/Twitter、JSON-LD 等核心能力。
  - 双语（en/zh）路由与页面元信息结构统一，工程可维护性好。
  - 已做历史 URL 301 跳转，减少旧页面 404 与权重流失风险。
- **主要风险**：
  - 站点结构中存在“模板页数据（templatePages）”但未落地为可索引页面，长尾词覆盖不足。
  - `sitemap` 的 `lastModified` 含手工常量日期，可能与真实内容更新时间不一致。
  - 结构化数据类型偏保守（首页只含 SoftwareApplication+FAQ），缺少 `WebSite` + `SearchAction` 等品牌/站点级信号。
  - 尚未看到显式 performance/UX SEO（CWV）策略说明与监控落地。

---

## 2) 审查范围与方法
- 代码静态审查（Next.js App Router、metadata、sitemap/robots、内容模型、结构化数据、跳转与路由）。
- 未包含线上抓取（如 GSC/GA 实际数据、日志、真实抓取预算消耗），因此部分结论为“代码层推断”。

---

## 3) 分维度详细审查

## A. 技术 SEO（Technical SEO）
### A1. 可抓取性与索引控制
**现状**
- `robots.ts` 已允许全站并禁止 `/api/`，并声明 `sitemap` 与 `host`。
- 页面 metadata 默认 `index/follow: true`。

**评价**：✅ 基础正确。

**建议**
1. 若未来出现参数化页面（如编辑器 query 组合）被搜索引擎重复抓取，建议明确 URL 参数治理（canonical 或 noindex 规则）。
2. 预留 staging/preview 环境 robots 防误收录机制（环境变量控制 noindex）。

### A2. Sitemap 策略
**现状**
- 静态页、博客列表分页、博客详情均进入 sitemap。
- `priority` 与 `changeFrequency` 有分层。

**风险点**
- `DEFAULT_LAST_MODIFIED` / `DICE_ROLLER_LAST_MODIFIED` 为硬编码常量；若后续内容更新未同步，`lastmod` 可信度下降。
- 首页 `lastModified` 目前从 FAQ 时间推导，不等于首页真实更新时间。

**建议**
1. 将关键页面更新时间改为“内容源自动计算”（页面模型、Git 提交时间、CMS 字段）而非常量。
2. 为首页、工具页建立独立更新时间来源，避免“借 FAQ 时间”导致误导。

### A3. Canonical / Hreflang
**现状**
- 首页、FAQ、Privacy 页面均有 canonical 与语言 alternates。
- 中英版本路径稳定（`/` 与 `/zh` 体系）。

**评价**：✅ 架构正确。

**建议**
1. 对所有可索引详情页（尤其博客详情）进行抽样确认：canonical 指向自我、hreflang 双向互链、x-default（可选）策略是否一致。
2. 统一 URL 末尾斜杠策略（目前看是无斜杠），避免边缘重复 URL。

### A4. 重定向与历史 URL 继承
**现状**
- 旧博客 slug、`/dice-roller` 路径均做 301 永久跳转。

**评价**：✅ 对历史权重回收有帮助。

**建议**
- 对“旧内容批量并到 /blog”做一次外链价值评估；若旧页有较多外链，优先跳至最相关新文而非博客首页。

---

## B. On-Page SEO（页面要素）
### B1. Title / Description
**现状**
- 全站 metadata 结构完整。
- 首页标题有核心关键词（Token Maker / VTT / DnD / Roll20 / Foundry）。

**评价**：✅ 覆盖核心主词不错。

**建议**
1. 对博客页、工具页执行“去模板化”标题策略：优先满足搜索意图而非品牌堆叠。
2. 建立标题长度与描述长度 lint（如 title 45~60 字符、description 120~160 字符英文场景）。

### B2. Headings 与语义结构
**现状**
- 首页内容块较多（Hero、SEO content、showcase），具备承载语义的空间。

**风险点**
- 未在本次审查中逐页确认 H1 唯一性与层级（需组件级抽查）。

**建议**
- 建立自动化快照测试：每个可索引页面仅 1 个 H1，H2/H3 层级不跳级。

### B3. 图片 SEO
**现状**
- 存在大量图片资源（博客封面、内页图、展示图等）。

**风险点**
- 仅从当前抽查无法确认图片 alt 的完整率。
- OG 图目前大量复用同一张 `/opengraph-image.png`，社媒点击吸引力可继续提升。

**建议**
1. 对博客封面和关键内文图建立“必填 alt”规范。
2. 为高价值页面（首页、dice-roller、核心博客）生成差异化 OG 图（标题可读、品牌一致）。

---

## C. 内容 SEO（Content & Topical Authority）
### C1. 主题集群与信息架构
**现状**
- 已有 blog 内容与双语版本。
- `templatePages` 数据结构非常适合承接“工具意图长尾词”（circle/square/hex/monster/transparent token maker）。

**关键机会**
- 这些模板页数据目前更像“内容资产”，尚未完全转化为可索引着陆页。

**建议（高优先级）**
1. 将 `templatePages` 实际路由化（例如 `/templates/[slug]` + `/zh/templates/[slug]`），每页独立 metadata、结构化数据、内链与 CTA。
2. 每个模板页聚焦 1 个主词 + 3~5 个语义相关词，避免与首页关键词内耗。
3. 在博客与模板页之间建立双向内链（教程 -> 工具模板、模板 -> 深度教程）。

### C2. E-E-A-T / 信任信号
**现状**
- 有隐私页与 FAQ，具备基本可信度要素。

**建议**
- 增加“内容维护时间线/作者说明/更新日志”模块，尤其是规则类文章（如 DnD 规则解释）以降低过时风险感知。

---

## D. 结构化数据（Schema）
### D1. 已有能力
- 首页有 `SoftwareApplication` + `FAQPage`。
- 页面组件支持通用 JSON-LD 注入。

### D2. 提升建议
1. 新增站点级 `WebSite`（可含 `SearchAction`，若站内搜索存在）。
2. 博客详情页确保 `Article`/`BlogPosting`（含 `datePublished`、`dateModified`、`author`、`image`、`inLanguage`）。
3. FAQ 页面可考虑补充 `BreadcrumbList`（若已展示面包屑，结构化数据应同步）。

---

## E. 多语言 SEO（International SEO）
**现状**
- 中英双语架构清晰，metadata locale 与 `lang` 设置合理。

**建议**
1. 确保每一对中英对应页面内容语义对齐，不仅是标题翻译。
2. 对中文页关键词进行本地化，而非英文词直译（例如“VTT token 制作器”与“跑团头像素材裁切工具”等词群并用）。

---

## F. 性能与体验 SEO（Core Web Vitals）
**现状**
- 代码中含 GA 接入，但未见 CWV 专项采集逻辑。

**建议**
1. 接入 `web-vitals` 上报（LCP/INP/CLS）到 GA 或自建端点。
2. 为首页首屏图像、关键字体、主交互组件建立性能预算。
3. 持续用 Lighthouse CI / PageSpeed API 做回归。

---

## G. 分析与增长闭环
**现状**
- 已有 GA 基础事件（上传、选框、下载）。

**建议**
1. 增加 SEO 漏斗事件：`landing_from_organic`、`cta_click`、`scroll_depth`、`template_page_enter`。
2. 将“下载 token”按入口页面分组，识别高转化 SEO 页面。

## 4) 优先级行动清单（90 天）

### P0（1~2 周）
- 把 sitemap `lastmod` 从常量改为可追踪内容更新时间源。
- 抽样校验所有博客详情 canonical/hreflang。
- 建立标题/描述长度与空值检查脚本（CI）。

### P1（2~6 周）
- 路由化模板着陆页（en/zh 双语），上线 5~10 个高意图页。
- 为核心页面制作差异化 OG 图。
- 为博客详情完善 `BlogPosting` JSON-LD 字段。

### P2（6~12 周）
- 建立 CWV 监控与性能预算。
- 构建 SEO 内容内链系统（工具页 ↔ 教程页 ↔ FAQ/隐私/主页）。
- 基于 GSC 查询词进行二次内容扩展（问题型长尾词）。

## 5) 可量化 KPI 建议
- 非品牌自然流量（sessions）
- Search Console 展现量 / 点击率（按页面类型：首页、模板页、博客）
- Top 20 关键词排名数量
- Organic landing -> token 下载转化率
- CWV 通过率（75 分位）

---

## 6) 结论
该项目在 **技术 SEO 基础层** 已达可持续迭代水平；下一阶段的增长天花板主要取决于：
1) 是否把已有内容资产（模板数据）转化为可索引的意图着陆页；
2) 是否建立可验证的更新/性能/结构化数据闭环。

若以上两项落地，预期在中长期可显著提升非品牌词覆盖与自然流量质量。
