# 批处理逐张编辑设计

## 目标

在现有批处理界面中同时提供两条路径：用户可以点击缩略图逐张编辑并确认，也可以继续一次性处理全部未完成图片。

## 已确认交互

- 上传多张图片后自动选中第一张。
- 点击任意缩略图会把对应图片载入现有编辑器画布。
- 切换图片时自动保存当前图片的完整视觉草稿，但不会自动把它标记为已完成。
- “完成当前并下一张”只渲染当前图片，成功后选择下一张未完成图片。
- “全部处理”继续一次性处理全部未完成图片：有独立草稿的图片使用自己的草稿，未编辑图片使用当前公共样式的默认构图。
- 已完成图片可以重新打开；只有视觉草稿实际变化时，旧渲染结果才失效。
- 导出尺寸在整个批次内统一；图片位置、缩放、文字、边框、遮罩、颜色、透明度和预设选择按图片独立保存。
- 缩略图显示当前、草稿、已完成和失败状态。
- 处理期间禁止切换、添加、删除、清空、重试或再次开始处理。

## 架构边界

### 批处理草稿

新增纯数据 `BatchVisualDraft`。它只保存可独立编辑的视觉字段，不保存 `File`、`HTMLImageElement`、object URL、导出尺寸、选中控件状态或 Zustand action。文字数组在捕获和恢复时深拷贝，避免不同图片共享可变引用。

### 批处理 Store

批处理 Store 继续拥有队列、当前条目 ID、每项草稿、渲染状态和 PNG 产物。Store 暴露明确 action，不直接读写编辑器 Store：选择条目、保存草稿、处理当前、处理全部、删除和清空。

保存草稿时先比较视觉字段。草稿未变化则保留现有 `done` 产物；草稿变化时释放旧 `renderedUrl`、清空 Blob，并把条目恢复为待处理状态。

### 编辑器会话适配器

新增批处理专用适配器作为两个 Store 之间的唯一边界。它负责：

1. 从编辑器捕获 `BatchVisualDraft`。
2. 从 `BatchItem.file` 创建编辑器自有的 object URL 和 `HTMLImageElement`。
3. 把图片与草稿一次性恢复到编辑器。
4. 使用加载 revision 丢弃过期的异步切换结果，并释放过期 URL。

批处理缩略图 URL 仍由批处理 Store 拥有，绝不直接交给编辑器，以免删除队列项后画布引用已释放 URL。

### 渲染器

渲染器接收 `BatchItem`、该图片的 `BatchVisualDraft`、共享的自定义边框资源和统一导出尺寸，构造临时 `EditorState` 后导出 PNG。渲染器不读取 Zustand Store，也不改变队列状态。

### UI

`BatchPanel` 只调度公开接口：切换前保存草稿、载入目标图片、完成当前并前进、全部处理剩余图片。复杂的数据转换与渲染不写在组件中。

删除当前图片后选择其后第一张可用图片；若当前图片是最后一张，则选择前一张。队列只剩一张时不再自动退出批处理。

## 错误与并发

- 选择不存在的条目 ID 立即抛出包含 ID 的错误。
- 处理没有加载完成的图片时立即抛出包含文件名的错误。
- 同一时间只允许一个单项或全量处理流程。
- 图片切换失败时保留当前选中 ID，并在对应条目显示明确错误，不吞异常。
- 删除、清空或退出时释放批处理产物 URL；编辑器图片 URL 继续由编辑器 Store 负责释放。
- ZIP 继续只收集 `done` 条目，不改变文件名和 ZIP 命名规则。

## 范围

### 修改范围

- 批处理类型、草稿纯函数、渲染器和 Store。
- 批处理编辑器适配器。
- `BatchPanel`、中英文文案和对应测试。

### 不修改

- 普通单图编辑流程。
- `Canvas.tsx` 和 `EditorLayout.tsx` 现有未提交改动。
- Coat Maker、博客、SEO、分享页、ZIP 命名和导出格式。
- 不新增依赖，不提交 commit。

## 验收与验证

- 缩略图切换、草稿恢复、草稿变更失效旧产物、删除当前项回退、单项完成并前进、全量处理剩余项均有自动化测试。
- 运行相关 Vitest、全量 Vitest、ESLint 和 Next.js build。
- 使用本地浏览器验证逐张切换、自动保存草稿、单项完成、全部处理和 ZIP 按钮状态。
