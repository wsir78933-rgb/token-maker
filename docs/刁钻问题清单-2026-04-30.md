# Token Maker 刁钻问题清单（2026-04-30）

## P0（高风险 / 误导搜索引擎）

1. **`/dice-roller-dnd` 的 sitemap `lastModified` 与页面真实更新时间没有直接关系**  
   当前逻辑把该页面的 `lastModified` 绑定为“该语言最新博客更新时间”，这会在工具页未改动时被动抖动，`lastmod` 信号可能被搜索引擎判定为低可信。  
   - 位置：`src/app/sitemap.ts` 中 `path === '/dice-roller-dnd'` 分支。

2. **博客 `datePublished` 与 `dateModified` 使用同一个字段**  
   `createBlogPostMetadata` 与 `buildBlogPostStructuredData` 都把发布时间和更新时间绑定到 `updatedAt`，会丢失“首次发布时间”语义。对新闻/文章型结果不友好。  
   - 位置：`src/lib/blog-content.ts`。

3. **类型检查脚本缺失但 PR 文案曾声称运行 typecheck**  
   `package.json` 没有 `typecheck` script，属于工程流程真实性风险（不是运行错误，但会误导维护者）。

---

## P1（中风险 / 可维护性与一致性）

4. **`DiceAnimatedDie` 的“伪随机函数”定义在组件内，每次渲染重新定义函数对象**  
   逻辑正确但有额外分配；可上提到模块作用域或独立 util，减少重复创建并便于复用测试。  
   - 位置：`src/components/dice/DiceAnimatedDie.tsx`。

5. **`createRollId` 依赖 `Date.now() + Math.random()`，理论上存在碰撞窗口**  
   高并发点击极端场景下存在重复 ID 风险，虽概率低但可替换为 `crypto.randomUUID()`（浏览器支持足够广）。  
   - 位置：`src/components/dice/DiceRollerTool.tsx`。

6. **`test-faces.js` 顶部用了 ESLint 禁用注释来绕过规则，不是根治**  
   目前可工作，但会长期积累“特例债务”；更规范方式是迁移到 ESM（`.mjs`）或在 eslint 配置里对脚本目录单独设规则。  
   - 位置：`test-faces.js`。

---

## P2（低风险 / 质量细节）

7. **`BatchPanel` 缩略图 `Image` 统一 `unoptimized`，性能策略过于粗糙**  
   对本地 blob URL 合理，但若未来混入远程 URL，会绕过优化链路。建议按 URL 类型动态判断。  
   - 位置：`src/components/editor/BatchPanel.tsx`。

8. **SEO 审查文档已提交，但没有“验收回写机制”**  
   文档建议很多，缺少 checklist 状态字段（todo/in-progress/done），执行后难以追踪闭环。
   - 位置：`docs/seo-audit-2026-04-30.md`。

---

## 我建议你优先做的 3 件事

1. 给 blog 数据模型补 `publishedAt`，分离 `datePublished/dateModified`。  
2. 给 `/dice-roller-dnd` 建独立更新时间源（不要借博客时间）。  
3. 把 `typecheck` 真正接入 `package.json` 与 CI（例如 `tsc --noEmit`）。
