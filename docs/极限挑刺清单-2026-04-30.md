# Token Maker 极限挑刺清单（鸡蛋里挑骨头版）

> 目标：假设“线上稳定增长 + 可审计工程质量 + SEO 高可信信号”是硬标准，对当前项目做最苛刻视角的质检。

## 1) SEO / 搜索引擎信号层（最容易被忽视的细节）

1. **`sitemap` 的工具页更新时间仍是手工日期，不是自动来源**  
   你已经把工具页从“借博客更新时间”改成独立来源，这是进步；但来源依然是代码常量（`2026-03-30`），不是内容系统字段/提交元数据自动推导。  
   风险：长期仍需人工维护，极易忘记更新。  

2. **`pickLatestIsoDate` 对非法日期字符串无显式兜底**  
   目前依赖 `new Date(value).getTime()` 比较，若未来出现异常字符串，结果可退化为 `NaN` 比较路径。建议在比较前做 `Number.isFinite` 校验。  

3. **博客 `publishedAt` 已有字段但尚未全面落库**  
   目前是“可选字段 + 回退 updatedAt”，语义正确但仅完成框架。若不补全历史文章首发时间，实际 SEO 收益有限。  

4. **站点级 `WebSite` schema 缺少 `potentialAction`（SearchAction）**  
   若你后续有站内搜索，可补；没有的话可忽略。现在是“可用但不满配”。

5. **OG 图策略还是偏“模板化”**  
   高价值页面（核心工具页、重点博客）若共享或近似 OG 图，社媒 CTR 可能受限。

---

## 2) 信息架构与内容层（流量上限的真正瓶颈）

6. **`templatePages` 数据资产尚未完全路由化为可索引页面**  
   你有结构化数据源，但没看到完整的模板落地路由矩阵（如 `/templates/[slug]` 双语全量）。这直接限制长尾承接。  

7. **中英文术语一致性有潜在“直译感”**  
   部分中文文案仍偏英文概念映射，不是搜索语境优先（例如“token maker”对“跑团头像/棋子裁切”的本地词覆盖可更强）。

8. **内容更新节奏没有机器可读的 changelog 信号**  
   对“规则类文章”（DND 机制）尤为关键，否则用户和搜索引擎都难判断“是否已过时”。

---

## 3) 前端实现与可测试性（看起来能跑，但不够抗变）

9. **`createRollId` 仍使用 `Date.now() + Math.random()`**  
   低概率碰撞，但在高并发自动化/回放场景里不是最佳实践。建议 `crypto.randomUUID()`。

10. **`DiceAnimatedDie` 组件内定义 `seededUnit` 函数**  
    每次渲染都会重新创建函数对象，虽小但属于“可避免开销”。可抽出到 util 或模块级纯函数。

11. **测试对 UI copy 文案耦合较高**  
    虽比之前版本好，但仍依赖按钮文案匹配。未来文案改字会引发无意义失败。可增加 `data-testid` 或语义 role + region 方案降低耦合。

12. **测试里覆盖 `Element.prototype.animate` 是全局猴子补丁**  
    可工作但要注意跨测试污染。建议集中到 test setup 并在 afterEach 恢复。

---

## 4) 工程流程与“可信交付”层（最容易翻车）

13. **PR 描述历史上出现过“声明已跑某命令”与真实不一致的问题**  
    你已经补了 `typecheck`，但流程层建议：把 lint/typecheck/test/build 统一挂 CI，PR 模板引用 CI 结果而非手工描述。

14. **`test-faces.js` 通过 eslint disable 规避规则是技术债标记**  
    建议迁移到 `.mjs` 或对脚本目录单独 eslint override，避免长期“注释豁免”扩散。

15. **缺少对 SEO 关键规则的自动化守卫**  
    建议加：
    - canonical/hreflang 快照断言；
    - JSON-LD schema shape 校验；
    - sitemap URL 数量与 lastmod 格式校验。

---

## 5) 可执行改进（按优先级）

### P0（本周）
- 把工具页 `lastmod` 切到真实来源（内容模型字段或 git 提交时间自动提取）。
- 在 CI 强制跑 `npm run lint && npm run typecheck && npm test`。
- 为历史 blog 补齐 `publishedAt` 数据（至少 top 流量文章）。

### P1（两周）
- 统一 SEO 断言测试（metadata/schema/sitemap）。
- 将 `seededUnit` 抽为 util，`createRollId` 升级为 `crypto.randomUUID()`。
- 降低文案耦合测试，补关键交互 testid。

### P2（一个月）
- 路由化模板页并建立双语内链体系。
- 为核心页面生成差异化 OG 图。
- 内容层引入更新日志与版本注记。

---

## 6) 一句话结论
**项目目前属于“能跑、可优化、但离‘高可信可持续增长系统’还有一段距离”。**  
最大短板不在功能，而在：**SEO 信号自动化、内容结构化落地、流程可验证性** 三件事。
